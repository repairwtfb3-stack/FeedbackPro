# FeedbackPro — T3: схема эмпирического корпуса

Статус: **CANONICAL DATA CONTRACT / NO SOFTWARE DEPENDENCY**

Этот контракт нужен для воспроизводимого анализа главы 2. Он не требует использования конкретной программы.

## 1. Основные поля

| Поле | Тип | Обязательность | Пример формата |
|---|---|---|---|
| `record_id` | строка/целое | MUST | `0001` |
| `external_id` | строка | IF AVAILABLE | ID площадки |
| `source_group` | enum | MUST | `site`, `marketplace`, `review_service`, `direct` |
| `source_name` | строка | OPTIONAL | название площадки |
| `review_date` | дата | MUST | `2026-03-14` |
| `author_anon` | строка | MUST | `A-0001` |
| `rating` | число 1–5 | OPTIONAL | `4` |
| `text` | текст | MUST | обезличенный текст |
| `duplicate_flag` | yes/no | MUST | `no` |
| `include_flag` | yes/no | MUST | `yes` |
| `exclusion_reason` | строка | IF EXCLUDED | `duplicate` |

## 2. Исследовательские коды

| Поле | Значения |
|---|---|
| `sentiment` | `POS`, `NEU`, `NEG`, `MIX` |
| `aspects` | список кодов из codebook |
| `criticality` | `C1`, `C2`, `C3`, `C4` |
| `criticality_reason` | краткое обоснование для C3/C4 |
| `response_visible` | `yes`, `no`, `unknown` |
| `requires_escalation` | `yes`, `no`, `unclear` |
| `coder_note` | комментарий кодировщика |
| `codebook_version` | например `T3-v1.0` |

## 3. Контроль качества данных

Перед анализом формируется отчет:
- исходное количество записей;
- количество записей вне периода;
- количество дублей;
- количество записей без содержательного текста;
- количество исключенных по иным причинам;
- итоговый аналитический корпус;
- доля записей с рейтингом;
- количество записей по каждому каналу.

Целевой итоговый корпус: **1200**; допустимый диапазон: **1000–1500**.

Если после очистки остается менее 1000 отзывов, Gate T3 не считается пройденным без отдельного методического решения.

## 4. Защита от подмены данных

Запрещено:
- дополнять корпус синтетическими отзывами ради достижения объема;
- создавать вымышленные оценки/даты/каналы;
- дублировать одну запись для увеличения выборки;
- изменять текст так, чтобы поменялся смысл;
- присваивать отсутствующий рейтинг;
- выдавать автоматически сгенерированную разметку за экспертную.

Допускается только техническая нормализация, не изменяющая содержание: единая кодировка, удаление лишних пробелов, обезличивание и явная маркировка дублей/исключений.
