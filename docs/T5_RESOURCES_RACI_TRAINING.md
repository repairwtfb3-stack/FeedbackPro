# Методика ЕГ — T5: ресурсы, матрица ответственности и обучение

Статус: **T5 IMPLEMENTATION CONTROL**

## 1. Категории ресурсов

Для пилота и последующего внедрения требуются ресурсы пяти типов.

### 1.1 Организационные
- sponsor/куратор;
- владелец процесса;
- координатор пилота;
- профильные владельцы процессов;
- PR/коммуникационная функция;
- клиентский сервис;
- аналитическая функция;
- legal/compliance/ПДн;
- администратор используемого реестра/системы.

### 1.2 Данные
- доступ к выбранным каналам;
- исторический baseline;
- правила provenance;
- справочник каналов и объектов;
- обезличивание/ограничение доступа.

### 1.3 Методические
- T4 TO-BE;
- классификатор;
- C1–C4 triggers;
- RACI;
- регламент;
- KPI formulas;
- инструкции по спорным случаям.

### 1.4 Технические
Технологически нейтральный минимум:
- единый реестр или workflow-система;
- средство хранения evidence;
- механизм отчётности;
- контролируемый доступ.

Конкретный стек не является результатом ВКР.

### 1.5 Временные
Не фиксируются вымышленные человеко-часы. До пилота организация оценивает:
- время первичной обработки;
- время экспертной верификации C3/C4;
- время профильных исполнителей;
- время контроля;
- нагрузку аналитика/координатора.

## 2. RACI внедрения

Роли:
- `SP` — sponsor;
- `PO` — владелец процесса;
- `PC` — координатор пилота;
- `PR` — PR/коммуникации;
- `CS` — клиентский сервис;
- `BO` — профильный владелец бизнес-процесса;
- `AN` — аналитик;
- `LC` — legal/compliance/ПДн;
- `SA` — администратор инструмента/реестра.

| Работа | SP | PO | PC | PR | CS | BO | AN | LC | SA |
|---|---|---|---|---|---|---|---|---|---|
| Утвердить scope пилота | A | R | C | C | C | C | C | C | I |
| Утвердить методику/KPI | I | A | R | C | C | C | R | C | I |
| Утвердить ПДн/доступ | I | C | R | I | I | I | I | A/R | C |
| Настроить реестр/систему | I | C | A | I | C | C | C | C | R |
| Провести обучение | I | A | R | R | R | R | C | C | C |
| Сформировать BEFORE | I | A | R | C | C | C | R | C | C |
| Вести пилот | I | A | R | R | R | R | C | C | C |
| C3/C4 verification | I | A | R | C | C | C | C | R/C | I |
| Контролировать качество данных | I | A | R | C | C | C | R | C | C |
| Сформировать AFTER | I | A | R | C | C | C | R | C | C |
| Оценить результат | C | A | R | C | C | C | R | C | I |
| Решение о масштабировании | A | R | C | C | C | C | C | C | I |

Фактические должности при внедрении сопоставляются с функциональными ролями. Эта RACI не описывает реальную текущую оргструктуру «Перекрёстка».

## 3. План обучения

### Модуль 1 — логика методики
Темы:
- зачем разделять отзыв, решение, response, action, outcome;
- provenance;
- жизненный цикл кейса.

### Модуль 2 — классификация
Темы:
- sentiment;
- multi-label aspects;
- C1–C4;
- отличие критичности от негативности;
- спорные случаи.

### Модуль 3 — маршрутизация и эскалация
Темы:
- owner;
- SLA;
- C3/C4 verification;
- legal/privacy triggers.

### Модуль 4 — коммуникация
Темы:
- публичный ответ;
- связь ответа с внутренним action;
- недопустимость закрытия кейса только фактом публикации ответа.

### Модуль 5 — контроль результата
Темы:
- control event;
- outcome;
- reopen;
- доказательство выполнения мероприятия.

### Модуль 6 — KPI и evidence
Темы:
- что измеряется;
- как формируется evidence;
- почему нельзя менять формулу после просмотра результата.

## 4. Проверка готовности участника

До допуска к пилоту участник должен:
- корректно классифицировать учебные примеры;
- объяснить различие C2/C3/C4;
- уметь определить маршрут эскалации;
- различать `response`, `action`, `outcome`;
- знать правила ПДн и минимизации данных;
- понимать, какие timestamps/status обязательны.

Фактические результаты обучения не выдумываются. При реальном пилоте они фиксируются в training evidence.

## 5. Dry-run

Перед стартом пилота проводится контролируемый dry-run на небольшом историческом наборе.

Цель:
- выявить неоднозначности codebook;
- проверить RACI;
- проверить доступы;
- проверить формирование evidence;
- проверить, что C3/C4 не закрываются без expert verification.

Dry-run не включается в AFTER и не используется для демонстрации эффекта методики.
