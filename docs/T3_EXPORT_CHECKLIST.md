# FeedbackPro — T3: чек-лист получения исходных выгрузок

Статус: **READY FOR DATA ACQUISITION**

Цель — получить реальные исходные записи за период **01.09.2025–31.08.2026** и привести их к `templates/T3_CORPUS_TEMPLATE.csv`.

## 1. Сайт / форма организации (`site`)

Нужна выгрузка из CMS/формы/системы отзывов сайта.

Минимально:
- дата;
- текст;
- оценка, если есть;
- исходный ID, если есть;
- URL/раздел/товар, если есть;
- ответ организации, если доступен.

Предпочтительный формат: CSV/XLSX/JSON.

## 2. Маркетплейс (`marketplace`)

Нужна выгрузка отзывов продавца/товаров организации за тот же период.

Минимально:
- ID отзыва;
- дата;
- рейтинг;
- текст;
- товар/артикул;
- ответ продавца, если доступен.

Открытый Wildberries dataset допускается только как внешний reference slice и не заменяет владельческую выгрузку организации N.

## 3. Сервис отзывов / карты / агрегатор (`review_service`)

Нужна выгрузка/экспорт отзывов карточки организации или исходная таблица мониторинга.

Минимально:
- дата;
- оценка;
- текст;
- филиал/карточка при наличии;
- ID/URL;
- ответ организации при наличии.

## 4. Прямой канал (`direct`)

Допустимые источники:
- анкета после покупки;
- форма обращения/обратной связи;
- CRM/служба поддержки;
- e-mail feedback;
- иная собственная точка контакта.

Минимально:
- дата;
- текст/комментарий;
- оценка, если есть;
- технический ID обращения;
- канал;
- результат/ответ, если есть.

Переписка и персональные данные должны быть обезличены до включения в исследовательский корпус.

## 5. Что не требуется заранее

Не нужно вручную присваивать:
- sentiment;
- aspects;
- criticality;
- requires_escalation.

Эти поля относятся к исследовательскому кодированию и заполняются после очистки корпуса по `T3_RESEARCH_PROTOCOL.md`.

## 6. Минимальная достаточность

Итог после очистки: **1000–1500 уникальных реальных отзывов**, целевой объём **1200**.

Не устанавливается искусственная квота 25% на каждый канал. Реальные доли каналов сохраняются как свойство фактического корпуса; важно, чтобы утвержденные используемые каналы были представлены и происхождение каждой записи было прослеживаемо.

Если конкретный канал фактически отсутствует у организации N, это должно быть зафиксировано как характеристика AS-IS, а не заполнено синтетическими записями. В таком случае методологическая рамка T3 корректируется явно до финального анализа.

## 7. После получения файлов

Последовательность неизменна:

**объединение → обезличивание → нормализация → dedup → inclusion/exclusion report → codebook → анализ → таблицы/диаграммы → P1–P8 → итоговая problem matrix → Gate T3.**
