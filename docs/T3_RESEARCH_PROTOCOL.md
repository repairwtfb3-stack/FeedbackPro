# FeedbackPro — T3: методика исследования корпуса и система кодирования

Статус: **CANONICAL ANALYTICAL PROTOCOL / READY FOR EMPIRICAL RUN**

## 1. Цель методики

Методика предназначена для анализа эмпирического корпуса отзывов организации N без программной обязательности. Основной метод — **структурированный контент-анализ с количественной группировкой** и последующим сопоставлением результатов с моделью AS-IS/T2.

## 2. Единица анализа

Единица анализа — один уникальный клиентский отзыв/сообщение обратной связи в пределах утвержденного периода 01.09.2025–31.08.2026.

Если один и тот же отзыв повторно опубликован/экспортирован из одного источника, дубль не считается самостоятельной единицей анализа.

## 3. Включение и исключение

### Включается
- отзыв относится к организации N, товару, услуге или взаимодействию с ней;
- дата входит в исследовательский период;
- присутствует содержательный текст;
- источник относится к утвержденной группе каналов;
- персональные данные обезличены.

### Исключается
- техническая запись без смыслового текста;
- явный дубль;
- рекламный спам;
- сообщение вне периода;
- материал, который нельзя надежно связать с исследуемым объектом;
- запись, содержащая персональные данные, если их невозможно безопасно обезличить.

Количество исключенных записей и причины исключения фиксируются отдельно.

## 4. Минимальная схема корпуса

| Поле | Обязательность | Правило |
|---|---|---|
| `record_id` | MUST | внутренний уникальный номер |
| `external_id` | IF AVAILABLE | исходный ID площадки |
| `source_group` | MUST | site / marketplace / review_service / direct |
| `source_name` | IF AVAILABLE | конкретная площадка, если допустимо раскрывать |
| `review_date` | MUST | дата публикации/получения |
| `author_anon` | MUST | обезличенный идентификатор |
| `rating` | OPTIONAL | 1–5 только если есть в источнике |
| `text` | MUST | обезличенный текст |
| `duplicate_flag` | MUST | yes/no |
| `include_flag` | MUST | yes/no |
| `exclusion_reason` | IF EXCLUDED | причина исключения |

## 5. Кодирование содержательной части

Для включенных отзывов добавляются исследовательские коды.

### 5.1 Тональность

| Код | Категория |
|---|---|
| `POS` | положительная |
| `NEU` | нейтральная/информационная |
| `NEG` | отрицательная |
| `MIX` | явно смешанная, если сведение к одной полярности искажает содержание |

Для итоговых трехкатегорийных сравнений `MIX` анализируется отдельно или по заранее зафиксированному правилу; его нельзя произвольно переносить в POS/NEG после просмотра результатов.

### 5.2 Аспекты

Multi-label: один отзыв может иметь несколько кодов.

Базовые коды:
- `QUALITY` — качество товара/услуги;
- `PRICE` — цена/условия покупки;
- `DELIVERY` — доставка/сроки;
- `SERVICE` — обслуживание/сервис;
- `STAFF` — персонал;
- `SUPPORT` — поддержка/обратная связь;
- `RETURN` — возврат/возмещение/претензия;
- `DIGITAL` — сайт/приложение/цифровой канал;
- `AVAILABILITY` — наличие/ассортимент;
- `OTHER` — иная тема.

Перед финальным анализом допускается уточнение справочника по фактическому материалу. Любое объединение/разделение категорий документируется до построения итоговых диаграмм.

### 5.3 Критичность

| Код | Уровень | Правило |
|---|---|---|
| `C1` | низкая | локальное замечание без существенного ущерба/эскалации |
| `C2` | средняя | повторяемость, заметное неудовлетворение, необходимость участия профильного подразделения |
| `C3` | высокая | существенный ущерб, финансовый конфликт, высокая публичность, повторная нерешенная проблема или значимое нарушение процесса |
| `C4` | критическая | потенциально серьезный правовой, безопасностный, массовый или репутационный эффект |

Критичность определяется не по эмоциональности текста, а по факторам из `T2_THEORETICAL_MODEL.md`.

### 5.4 Дополнительные исследовательские признаки

- `problem_repeat` — единичная/повторяющаяся тема, если повторяемость подтверждается корпусом;
- `response_visible` — есть ли публично видимый ответ организации, если источник позволяет это определить;
- `requires_escalation` — да/нет по T2-модели;
- `process_gap` — код отсутствующего/неформализованного элемента AS-IS, если вывод подтверждается материалом.

Эти признаки используются только при наличии фактических оснований.

## 6. Правила кодирования

1. Сначала читается полный текст отзыва, затем присваиваются коды.
2. Тональность, аспект и критичность кодируются независимо.
3. При сомнении кодировщик фиксирует комментарий, а не «угадывает» категорию.
4. Для C3/C4 обязательно краткое текстовое обоснование.
5. `OTHER` не должен становиться скрытым контейнером для значимой новой категории; если таких случаев много, справочник пересматривается до финального анализа.
6. Категории нельзя менять постфактум только ради более «красивой» статистики.
7. Все изменения codebook фиксируются версией/датой.

## 7. Контроль качества кодирования

Базовый вариант:
- основная кодировка выполняется по единому codebook;
- спорные случаи помечаются для повторного просмотра;
- до финальной статистики проводится повторная проверка всех C3/C4 и выборочная проверка остальных категорий.

Контрольная экспертная выборка до **300 отзывов** используется только если такая процедура фактически проводится. В таком случае фиксируются состав выборки, правила отбора и результаты экспертной проверки. Синтетическая экспертная разметка запрещена.

## 8. Количественный анализ

Минимальные методы:
- абсолютные частоты;
- доли/проценты;
- распределение по каналам;
- распределение по оценкам;
- распределение по тональности;
- частоты аспектов;
- распределение критичности;
- кросс-табуляции `аспект × тональность`, `аспект × критичность`, `канал × тональность`, `канал × критичность`;
- временная динамика по месяцам, если наполнение месяцев достаточно для интерпретации.

Статистическая значимость не декларируется без отдельной обоснованной процедуры. Описательная аналитика является базовой и достаточной для выявления структуры корпуса и проблем процесса.

## 9. Правило доказательства проблемы

Проблема главы 2 считается подтвержденной только если есть минимум два типа основания из трех:

1. **процессное основание** — элемент AS-IS отсутствует/неформализован;
2. **эмпирическое основание** — структура корпуса показывает повторяемость, концентрацию, критические случаи или иное измеримое проявление;
3. **научно-нормативное основание** — проблема противоречит подходам/рекомендациям, подтвержденным научной или нормативной базой.

Если доступно только одно основание, формулировка должна быть осторожной: `риск`, `ограничение`, `гипотеза проблемы`, а не доказанная проблема.

## 10. Воспроизводимость

Для каждого итогового числа главы 2 должно быть возможно восстановить:
- исходный набор записей;
- правила включения/исключения;
- версию codebook;
- формулу расчета;
- фильтр/группировку;
- дату формирования результата.

Никакие проценты, средние значения, распределения и «топы» не заполняются до фактического корпуса.
