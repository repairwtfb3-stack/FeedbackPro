## 2. План диаграмм

1. Структура корпуса по каналам — столбчатая диаграмма.
2. Динамика количества отзывов по месяцам — линейная/столбчатая.
3. Распределение оценок — столбчатая.
4. Тональность — столбчатая.
5. Топ аспектов — горизонтальная столбчатая.
6. Аспект × тональность — тепловая карта или сгруппированная диаграмма.
7. Критичность C1–C4 — столбчатая.
8. Аспект × критичность — тепловая карта.
9. Каналы × отрицательная тональность/высокая критичность — сравнительная диаграмма.

Круговые диаграммы не используются автоматически: только если они действительно улучшают читаемость малой структуры категорий.

## 3. Кандидатные проблемы до эмпирической проверки

Ни одна строка ниже не считается доказанной только потому, что она включена в план.

| ID | Гипотеза проблемы | Возможная причина | Возможное последствие | Требование к TO-BE при подтверждении |
|---|---|---|---|---|
| P1 | Разрозненность каналов и учета | отдельный просмотр источников, ручной перенос | задержки, дублирование, потеря контекста | единая регистрация и provenance по всем каналам |
| P2 | Нет единой классификации | визуальная оценка и ручная тематизация без codebook | несопоставимые решения и аналитика | единый классификатор тональности/аспектов/критичности |
| P3 | Негативность подменяет приоритет | формальная критичность отсутствует | риск пропуска значимого нейтрального/смешанного сигнала | отдельная шкала C1–C4 и триггеры эскалации |
| P4 | Решения не прослеживаются | разрозненная реакция по каналам | невозможно связать отзыв с действием и результатом | цепочка отзыв → решение → мероприятие → результат |
| P5 | Нет единого контроля исполнения | отсутствует централизованный статус/срок/владелец | незакрытые или повторяющиеся проблемы | статус, ответственный, срок, контроль результата |
| P6 | Аналитика формируется эпизодически | данные не агрегированы по единой схеме | слабая выявляемость системных проблем | регулярные агрегаты, тренды, KPI и проблемные аспекты |
| P7 | Коммуникационный ответ не связан с внутренним исправлением | ответ и мероприятие существуют отдельно | публичная реакция без устранения причины | разделение и связка `ответ` + `мероприятие` |
| P8 | Риски ПДн/претензий не встроены в процесс | нет формальных правил обработки чувствительных случаев | правовые/репутационные риски | обезличивание, юридическая эскалация, правила доступа |

## 4. Критерий перехода гипотезы в доказанную проблему

Для каждой P1–P8 заполняется карточка:

`проблема → процессное evidence → эмпирическое evidence → научно-нормативное evidence → вывод → требование TO-BE`.

Статусы:
- `HYPOTHESIS` — только предварительное предположение;
- `SUPPORTED` — есть минимум два типа evidence;
- `NOT CONFIRMED` — фактические данные не подтверждают проблему;
- `OUT OF SCOPE` — проблема не относится к предмету ВКР.

## 6. Правило написания выводов

Выводы главы 2 не должны начинаться с решения FeedbackPro. Сначала фиксируется факт/структура данных, затем проблема, затем причина/последствие, и только после этого формируется требование к главе 3.

Каноническая логика:

**данные → наблюдение → проблема → причина → последствие → требование к TO-BE**.
